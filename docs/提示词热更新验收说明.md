# 提示词热更新验收说明

## 本次解决的问题

MallAgent 现在可以在不重启进程的情况下发布提示词新版本、查看历史版本并切换回旧版本。版本正文不可覆盖，保证诊断记录中的版本号始终能还原出当时使用的提示词。

## 内部接口

接口统一使用 `Authorization: Bearer <AGENT_CONTROL_API_KEY>`，并透传或生成 `X-Trace-Id`。

| 操作 | 方法与地址 | 入参 | 结果 |
| --- | --- | --- | --- |
| 查看历史 | `GET /internal/v1/prompts?limit=50` | 无 | 版本号、是否当前版本、发布时间 |
| 查看当前正文 | `GET /internal/v1/prompts/current` | 无 | 当前版本号和提示词正文 |
| 发布新版本 | `POST /internal/v1/prompts` | `{"version":"v2","prompt":"..."}` | 新版本立即成为当前版本 |
| 切换或回滚 | `POST /internal/v1/prompts/v1/activate` | 无 | 历史版本重新成为当前版本 |

## 业务验收场景

1. 新建诊断 A，确认其版本快照为 `v1`。
2. 发布 `v2`，无需重启 MallAgent。
3. 新建诊断 B，确认其版本快照为 `v2`；继续执行诊断 A，确认仍使用 `v1`。
4. 激活 `v1`，新建诊断 C，确认使用 `v1`。
5. 再次发布同名 `v1`，接口应拒绝，原正文不能被覆盖。
6. 输入非法版本号、空正文或超过 60000 字符的正文，接口应拒绝。
7. 检查运行日志：应包含 TraceId、操作、版本号和正文长度，不应输出完整提示词正文。

## 暂不伪造的能力

Skill 与 Tool Schema 当前只有运行版本字符串，没有真实的内容注册表和加载器，因此本次没有把“修改版本标签”包装成热更新。待建立可校验的清单、不可变版本存储和运行快照后，再分别接入发布与回滚。
